## 1. 项目背景

成都拥有 2300 余年建城史、2 处世界文化遗产、180 余座博物馆，是联合国教科文组织认定的「世界美食之都」，也是全球唯一能在市区眺望 5000 米级雪山的超大城市。但现有宣传类站点普遍存在三个问题：

1. **信息分散**：景区在文旅局、交通在轨道集团、预约在各景区公众号，用户要在 5-8 个入口之间跳转。
2. **视觉同质**：大量站点套用同一套模板，缺乏城市辨识度。
3. **只"看"不"用"**：以图文罗列为主，缺少行程决策支持（几天怎么走、预算多少、下雨备选）。

本项目以"天府墨韵"为视觉主线，把**城市认知、活动日历、景区详情、行程攻略、美食、服务入口、交通换乘**收敛到一个网站内，并用轻量智能化能力降低决策成本。

## 3. 用户画像

### 3.1 画像 A：首次来蓉的外地游客（核心用户，占比约 55%）

- **基本信息**：25-35 岁，一二线城市白领，2-4 人结伴，停留 3-4 天。
- **目标**：4 天内看到最有代表性的成都（熊猫、火锅、都江堰、老街）。
- **痛点**：不知道景点之间距离、怕行程太赶、怕被"游客店"坑。
- **典型场景**：出发前 1 周在小红书/抖音刷到内容 → 搜"成都三天怎么玩" → 需要一份可照抄的路线。
- **对应功能**：游记攻略（三天两夜）、经典景区详情（门票/交通/时长）、特色美食（人均与避坑）、交通路线。

### 3.2 画像 B：本地文化爱好者（占比约 25%）

- **基本信息**：28-45 岁，成都本地或周边，周末出行，带孩子或父母。
- **目标**：找当季的活动（灯会、非遗节、音乐节），找近郊半日路线。
- **痛点**：活动信息分散在公众号，容易错过；亲子路线缺少节奏建议。
- **对应功能**：文化活动（月度分布 + 季节筛选）、游记攻略（亲子研学、博物馆雨天备选）。

### 3.3 画像 C：外地学生的家长/教师（占比约 20%）

- **基本信息**：35-50 岁，为研学或亲子游做功课。
- **目标**：确认安全信息、预约方式、紧急联系方式。
- **对应功能**：城市服务（预约入口、热线）、智能问答（"遇到紧急情况打什么电话"）。

## 6. 验收标准（Definition of Done）

1. 八个板块页面均可访问，内容无占位符（Lorem ipsum / TODO）。
2. 每类筛选与搜索至少有 3 条单测或 E2E 覆盖。
3. `pnpm typecheck`、`pnpm lint`、`pnpm test`、`pnpm exec playwright test` 全部通过。
4. `pnpm build` 产物可直接静态部署，无外链资源依赖。
5. Lighthouse 四项指标达到第 5 节阈值（HTTPS 项在本地环境豁免）。
6. 提交历史符合 Conventional Commits，存在 main/develop/feature 分支与 PR 合并记录。

## 7. 不做什么（范围边界）

- 不做后端与数据库：内容以 TS 模块维护，接口层用 `delay()` 模拟异步，便于后续替换真实 API。
- 不做用户体系：收藏与主题仅存 localStorage。
- 不做在线支付/预约闭环：只提供官方入口跳转。
- 不引入第三方 UI 框架与图床：视觉资源全部本地程序化生成。
