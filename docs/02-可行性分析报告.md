# 可行性分析报告

---

## 1. 技术可行性

### 1.1 技术选型与成熟度

| 技术 | 版本 | 成熟度 | 团队掌握情况 |
| --- | --- | --- | --- |
| Vue 3（Composition API） | 3.5.44 | 稳定，生态完善 | 已通过课程实验掌握组件与响应式 |
| Vite | 6.4.5 | 官方推荐构建工具 | 掌握配置、别名、分包 |
| TypeScript | 5.7.3 | 事实标准 | 掌握接口、泛型、工具类型 |
| Vue Router 4 | 4.6.4 | 官方路由 | 掌握动态路由与懒加载 |
| Pinia 2 | 2.3.1 | 官方状态管理 | 掌握 store/getter/action 与持久化 |
| Vitest + Playwright | 2.1.9 / 1.64 | 主流测试栈 | 已能编写断言与端到端用例 |

结论：全部为课程已覆盖或可在 2 天内掌握的技术，无学习悬崖。

### 1.2 关键技术难点与对策

| 难点 | 风险 | 对策 | 结果 |
| --- | --- | --- | --- |
| 无外网图床与字体，视觉素材从哪来 | 高：直接影响观感 | 用 Node 程序化生成 46 张 SVG（山脊 Catmull-Rom 平滑、剪影构件、7 套配色） | 46 张全部生成，单张 3-12 KB，零外部依赖 |
| 实时天气依赖第三方接口 | 中：断网/限流即空白 | 30 分钟 localStorage 缓存 + 6s 超时 AbortController + 离线兜底数据 | 断网仍可展示，页眉不空白 |
| 中文分词难，问答容易"答非所问" | 中：影响智能化评分 | 关键词加权 + 中文二元组 Jaccard 相似度双通道，阈值 5 分，未命中给兜底 | 「熊猫基地几点去最好」可命中 panda-time |
| 首屏图片多导致性能不达标 | 高：Lighthouse ≥ 80 硬指标 | 全部 SVG、懒加载、`aspect-ratio` 占位、代码分割、移除 feTurbulence 噪点 | 性能 87-99，CLS 0 |
| 移动端横向滚动 | 中 | grid/flex 子项 `min-width: 0`，滚动容器不参与 min-content 撑宽 | 11 个页面横向溢出均为 0 |
| 无头浏览器审计环境受限 | 中 | 通过 Playwright 启动本机 Edge 并暴露 CDP 端口给 Lighthouse | 审计可复现 |

### 1.3 环境要求

Node.js ≥ 20.19、pnpm 10、任意现代浏览器；构建产物为纯静态文件（`dist/` ≈ 1.2 MB，gzip 后约 300 KB），可部署到任意静态托管。

## 2. 经济可行性

| 项目 | 方案 | 成本 |
| --- | --- | --- |
| 开发工具 | VS Code、Git、Node、pnpm | 0 元（开源） |
| 框架与组件库 | Vue/Vite/TS/Pinia 全部 MIT | 0 元 |
| 图片素材 | 程序化生成 SVG，不使用商业图库 | 0 元（避免 200-2000 元/张的授权费） |
| 字体 | 使用系统字体（苹方/思源宋体回退），不引入 Web 字体 | 0 元，且节省 200-600 KB 网络传输 |
| 地图/天气 | open-meteo 免费公共接口，无 Key、无调用上限 | 0 元 |
| 域名与托管 | 课程演示可用 GitHub Pages / Vercel 免费额度 | 0 元 |
| 人力 | 4 人 × 约 30 小时 | 课程学分内 |

结论：**直接现金成本为 0**，主要成本是人力时间；相比采购素材与模板（预估 1000-3000 元）节省显著。

## 3. 进度可行性

总周期 5 周（S0-S5），与任务书六个阶段对齐：

| 阶段 | 时间 | 交付物 | 状态 |
| --- | --- | --- | --- |
| S0 需求与调研 | 第 1 周 | PRD、可行性分析、竞品分析、评审记录 | 已完成 |
| S1 信息架构与设计 | 第 2 周 | 站点地图、线框图、高保真稿、UI 规范 | 已完成 |
| S2 工程化基座 | 第 2 周末 | Vite+TS+Router+Pinia 基座、ESLint/Prettier、Conventional Commits、分支模型 | 已完成 |
| S3 页面与智能化 | 第 3-4 周 | 8 个板块 + 4 类详情页 + 3 类智能化能力 | 已完成 |

## 4. 风险与应对

| 风险 | 概率 | 影响 | 应对措施 | 实际发生 |
| --- | --- | --- | --- | --- |
| 视觉风格反复推翻 | 高 | 进度延期 | 先用 resvg 渲染 PNG 逐张验收 SVG，再进入页面开发 | 发生 3 次迭代（屋顶/熊猫/美食构图），已消化 |
| 依赖安装异常 | 中 | 无法构建 | 固定 lockfile、记录 `pnpm-workspace.yaml` overrides | 发生（estree-walker 提升冲突），已记录解决方案 |
| 浏览器自动化受限 | 中 | 无法交付测试证据 | 使用本机 Edge + CDP 端口 | 发生，已绕过 |
| 内容出现事实错误 | 中 | 扣分 | 交叉核对官方公开信息，页面标注"教学演示" | 未发生 |
| 一人承担全部工作 | 中 | 分工表失真 | 按模块划分 PR 并在报告中说明实际分工 | 见复盘 |

## 5. 可行性结论

技术栈成熟且与课程匹配，现金成本为零，进度与任务书阶段一致，主要风险（视觉素材、性能、中文匹配）均已给出可执行对策并落地验证。**项目具备完整的可行性，建议立项并按 S0-S5 推进。**
