## 2. 导航结构

### 2.1 四层导航

1. **辅助功能区（页眉第一行）**：实时天气胶囊、日期、无障碍模式、城市服务、智能助手、收藏数。
2. **主导航（页眉第二行）**：印章 Logo + 8 个栏目 + 全站搜索（快捷键 /）+ 主题切换 + 汉堡（<1100px）。
3. **边栏导航（主页左侧，≥1280px）**：9 个板块锚点 + 回到顶部，滚动高亮。
4. **页脚导航**：品牌介绍、浏览栏目（8 项）、服务热线（5 条）、关于本站（4 项）。

### 2.2 导航原则

- 任意页面到任意板块 ≤ 2 次点击（页眉 1 次）。
- 详情页固定提供「返回列表」与「相关推荐」两个出口，避免死路。
- 移动端收起主导航为抽屉，保留搜索与主题两个高频操作。
- 当前栏目高亮（aria-current 语义 + 视觉状态）。

## 4. 核心用户任务流

### 4.1 首次游客：从"想去"到"能照着走"

```text
进入主页
  → 主视觉「天府之国，三千年城名未改」建立印象
  → 下滑看城市数据与气质（30 秒认识这座城市）
  → 点「游记攻略」→ 三天两夜攻略
  → 攻略里跳「都江堰」详情，确认门票/时长/交通
  → 底部「交通路线」查犀浦换乘
  → 有疑问 → 右下角「问成都」→ 命中熊猫/地铁问答
```

### 4.2 本地用户：找本周活动

```text
主页 → 文化活动 → 看 12 个月分布图 → 点当前月 → 筛选「演出」
  → 川剧变脸详情 → 票价/剧场 → 收藏
```

### 4.3 家长：确认安全与预约

```text
搜索「预约」→ 结果分「服务」组 → 景区预约入口
  → 城市服务 → 服务热线（12345 / 120）
  → 问成都：「遇到紧急情况打什么电话」
```

## 5. 内容组织模型

所有内容被抽象为 5 类可检索实体，统一进入搜索索引：

| 实体 | 关键字段 | 卡片组件 | 详情页 |
| --- | --- | --- | --- |
| 景区 | 等级/区域/门票/时长/看点/提示 | ScenicCard | /scenic/:id |
| 美食 | 辣度/人均/区域/店铺 | FoodCard | /food/:id |
| 活动 | 月份/季节/分类/地点/票价 | EventCard | /culture/:id |
| 攻略 | 天数/预算/标签/分段路线 | GuideCard | /guides/:id |
| 服务 | 分类/官方入口/徽标 | ServiceCard | 外链 |

这一模型让「筛选」「搜索」「推荐」「相关推荐」四套交互复用同一份数据。
