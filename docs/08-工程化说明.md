# 工程化说明

---

## 1. 技术栈与选型理由

| 需求 | 选型 | 理由 |
| --- | --- | --- |
| 组件化 + 表单绑定 | Vue 3.5 + `<script setup>` | 任务书要求 Vue；组合式 API 逻辑复用更清晰；`defineModel` 天然支持 v-model |
| 构建 | Vite 6 | 冷启动 < 1s、HMR 毫秒级；生产构建基于 Rollup，天然支持代码分割 |
| 类型 | TypeScript 5.7（strict） | 数据模型集中在 types/index.ts，页面与卡片共享同一套类型 |
| 路由 | Vue Router 4 | history 模式 + 动态 import 分包 + scrollBehavior 精细化 |
| 状态 | Pinia 2 | 三个 store 职责单一；本地持久化逻辑收敛在 store 内 |
| 样式 | 原生 CSS + 令牌 | 课程要求掌握 CSS3；不用 UI 框架更能体现设计能力，也避免体积膨胀 |
| 测试 | Vitest + Playwright | 与 Vite 同源配置；E2E 用本机 Edge，无需下载浏览器 |

## 2. 目录结构与职责

```text
src/
├─ api/          与"后端"的边界：contentApi 模拟异步、weather 调第三方、search 建索引
├─ assets/       静态资源与样式（img 由脚本生成，styles 为三层 CSS 变量）
├─ components/
│  ├─ common/    与业务无关的通用件（卡片、轮播、面板、问答…）
│  ├─ cards/     领域卡片（景区/美食/活动/攻略/服务），只依赖 types 与公共件
│  └─ layout/    页眉、页脚、边栏、内页横幅
├─ composables/  可复用的响应式逻辑（SEO、滚动揭示、数字滚动、媒体查询、搜索）
├─ data/         内容数据源（TS 模块），页面不直接写文案
├─ router/       路由表 + 导航元数据（单一数据源）
├─ stores/       Pinia（app/weather/chat）
├─ types/        领域模型
├─ utils/        纯函数（可单测）
└─ views/        页面级组件，负责组合与编排
```

**依赖方向（严格单向）**：`views → components → composables/utils → stores/api → data/types`。禁止 data 反向依赖组件，保证数据层可在 Node 环境下被单测引用。

## 3. 代码规范

### 3.1 ESLint（flat config, ESLint 9）

- 基础：`@eslint/js` recommended + `typescript-eslint` recommended + `eslint-plugin-vue` flat/recommended。
- 关闭了与 Prettier 冲突的格式规则；开启 `vue/attribute-hyphenation`、`eqeqeq`、`prefer-const`。
- `vue/multi-word-component-names: off`（本项目的视图命名如 HomeView 已符合）。
- `vue/require-default-prop: off`（可选 props 用 TS 的 `?` 表达）。
- `--max-warnings 0`：警告即失败。

### 3.2 Prettier

```json
{ "semi": false, "singleQuote": true, "printWidth": 100, "trailingComma": "all" }
```

### 3.3 TypeScript

- `strict: true`、`noUnusedLocals`、`noUnusedParameters`、`noFallthroughCasesInSwitch`。
- 路径别名 `@/* → src/*`（vite.config.ts 与 tsconfig.app.json 双处配置）。
- `vue-tsc --noEmit` 作为 `pnpm build` 的前置门禁。

## 4. Git 工作流

### 4.1 分支模型

```text
main      ──●───────────────────────────●──────────►  仅接受 develop 的发布合并 + Tag
             \                         /
develop   ────●──●────●────●────●────●────────────►  集成分支，功能分支在此合并
               \  \    \    \    \    \
feature/*       ●  ●    ●    ●    ●    ●             每个功能一条分支，小步提交
```

| 分支 | 命名 | 规则 |
| --- | --- | --- |
| main | main | 受保护，禁止直接 push，只能从 develop 合并并打 tag |
| develop | develop | 受保护，功能分支通过 PR 合入 |
| feature | feature/<模块> | 如 feature/smart-module，完成后 PR 到 develop |
| hotfix | hotfix/<问题> | 从 main 切出，修完同时合回 main 与 develop |

### 4.2 提交规范（Conventional Commits）

```text
<type>(<scope>): <subject>

type: feat | fix | docs | style | refactor | perf | test | build | ci | chore | revert
scope: design | data | utils | api | store | composable | ui | router | pages | app | test | audit | repo
```

示例：`feat(api): 接入 open-meteo 实时天气并实现离线兜底缓存`

- `commitlint` 在 `commit-msg` 钩子校验 type 与 subject 长度（≤72）。
- `lint-staged` 在 `pre-commit` 钩子对暂存文件执行 `eslint --fix` 与 `prettier --write`。
- 本项目实际提交 27 个，覆盖 7 个 PR（详见 docs/分工与PR记录.md）。

### 4.3 代码评审（PR）要点

1. 是否引入新的外部依赖（需说明理由与体积影响）。
2. 是否所有交互元素可键盘访问、图片有 alt。
3. 是否有对应的单元测试或 E2E 用例。
4. 是否破坏既有类型（`vue-tsc` 是否通过）。
5. 是否影响 LCP/CLS（新增图片是否给了宽高比）。

## 6. 构建与产物

```text
dist/
├─ index.html                     ~1.4 KB
├─ assets/index-*.css             ~29 KB（gzip 6.8 KB）
├─ assets/index-*.js              ~140 KB（gzip 44 KB，含运行时与公共组件）
├─ assets/vue-vendor-*.js         ~110 KB（gzip 43 KB，手动分包）
├─ assets/HomeView-*.js           ~12 KB
├─ assets/ScenicView-*.js 等      ~3-10 KB / 页面（按路由分割）
└─ assets/hero-1-*.svg 等 46 张   ~3-12 KB / 张
```

优化手段：

1. `manualChunks` 把 vue/vue-router/pinia 拆为稳定 vendor 包，业务更新不影响缓存。
2. 路由级动态 import，首屏只加载 HomeView 与公共组件。
3. 全部 SVG 由 Vite 生成内容 hash，可长期缓存。
4. `cssCodeSplit`：每个页面只加载自己的 CSS。
5. 移除 SVG 中的 feTurbulence 噪点（Lighthouse 性能 69 → 87/99）。

## 7. 可维护性约定

- 单文件不超过约 700 行（最大为详情页 ~500 行，含样式）。
- 组件 props 必须带类型；事件用 `defineEmits` 声明。
- 涉及时区/日期的地方使用 `Asia/Shanghai` 语境（项目内不跨时区）。
- 所有 localStorage 读写包在 try/catch 中（隐私模式兼容）。
- 新增页面必须：注册路由（含 meta.title）→ 调用 useSeo → 提供面包屑 → 覆盖 375/768/1440 三档验证。
