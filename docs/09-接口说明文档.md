# 接口说明文档

本项目为纯前端应用，接口分为三类：**模拟后端接口（contentApi）**、**第三方公开接口（open-meteo 天气）**、**本地智能接口（搜索/问答/推荐）**。所有接口以 TypeScript 模块形式导出，返回 `Promise`，便于后续替换为真实 HTTP 请求。

---

## 1. 数据模型

见 `src/types/index.ts`，核心实体：

```ts
interface ScenicSpot {
  id: string; name: string; enName: string; level: string; area: string;
  img: ImgKey; summary: string; intro: string;
  highlights: string[]; tips: string[];
  ticket: string; openTime: string; duration: string;
  address: string; transport: string;
  rating: number; heat: number; tags: string[]; bestSeason: string;
}

interface Food {
  id: string; name: string; enName: string; img: ImgKey;
  summary: string; intro: string; price: string;
  spicy: 0 | 1 | 2 | 3; tags: string[]; districts: string[]; shops: string[];
  rating: number;
}

interface CultureEvent {
  id: string; name: string; img: ImgKey; month: number; season: string;
  place: string; duration: string; price: string; summary: string; intro: string;
  category: '节庆' | '演出' | '展览' | '赛事' | '民俗'; tags: string[];
}

interface Guide {
  id: string; title: string; subtitle: string; author: string; avatar: string;
  date: string; days: number; budget: number; season: string; tags: string[];
  img: ImgKey; excerpt: string;
  sections: { title: string; paragraphs: string[] }[];

  id: string; name: string; desc: string; icon: string;
  category: '出行' | '文旅' | '政务' | '生活'; link: string; badge?: string;
}
```

## 2. contentApi（模拟后端）

文件：`src/api/content.ts`

| 方法 | 入参 | 返回 | 说明 |
| --- | --- | --- | --- |
| getScenicSpots() | — | Promise<ScenicSpot[]> | 全部 10 个景区 |
| getScenicSpot(id) | string | Promise<ScenicSpot \| undefined> | 单个景区 |
| getFoods() | — | Promise<Food[]> | 11 种美食 |
| getFood(id) | string | Promise<Food \| undefined> | 单个美食 |
| getCultureEvents() | — | Promise<CultureEvent[]> | 9 个活动 |
| getCultureEvent(id) | string | Promise<CultureEvent \| undefined> | 单个活动 |
| getGuides() / getGuide(id) | — / string | Promise<Guide[]> / Guide | 6 篇攻略 |
| getServices() | — | Promise<CityService[]> | 12 项服务 |
| getTrafficRoutes() / getMetroLines() | — | Promise<TrafficRoute[]> / MetroLine[] | 交通数据 |

**行为约定**

- 所有方法内部经过 `delay(data, 220)`，模拟 220ms 网络延迟，用于验证加载态。
- 不抛错：查询不到返回 `undefined`，由页面渲染空状态。
- 页面当前直接引用 `src/data/*` 静态数据以便首屏零等待；contentApi 作为"可切换到真实后端"的适配层保留，替换时只需把页面 import 从 data 改为 api。

**错误处理**

| 场景 | 表现 |
| --- | --- |
| id 不存在 | 详情页渲染 EmptyState + 返回列表入口 |
| 数据为空 | 列表页渲染空状态 + 重置筛选按钮 |

## 3. 天气接口（open-meteo）

文件：`src/api/weather.ts`

### 3.1 请求

```text
GET https://api.open-meteo.com/v1/forecast
  ?latitude=30.6598
  &longitude=104.0633
  &current=temperature_2m,relative_humidity_2m,apparent_temperature,weather_code,wind_speed_10m
  &hourly=temperature_2m,weather_code&forecast_days=2
  &daily=weather_code,temperature_2m_max,temperature_2m_min&forecast_days=5
  &timezone=Asia%2FShanghai
```

- 无需 API Key；CORS 开放；成都坐标（天府广场）30.6598, 104.0633。

### 3.2 响应归一化

```ts
interface WeatherNow {
  city: string; temperature: number; apparent: number; humidity: number; wind: number;
  code: number; text: string; icon: string; updatedAt: string;
  source: 'online' | 'fallback';
  hourly: { time: string; temperature: number; code: number }[];
  daily: { date: string; max: number; min: number; text: string; icon: string }[];
}
```

- `code`（WMO 4677）经 `weatherText()` / `weatherIcon()` 转为中文与图标键（sun/sun-cloud/cloud/fog/drizzle/rain/snow/storm）。
- `hourly` 从当前小时起截取 8 条；`daily` 取 5 天。

### 3.3 缓存与降级

| 层 | 策略 |
| --- | --- |
| 内存 | store 内 10 分钟节流（`loadedAt`） |
| localStorage | `cd-weather-cache-v1`，TTL 30 分钟，含 `savedAt` |
| 超时 | AbortController 6 秒 |
| 失败 | 返回 `fallbackWeather()`：21°、多云、6 小时、5 天示例数据，`source: 'fallback'` |
| 承诺 | `fetchWeather()` 永不 reject，UI 永不空白 |

页眉展示 `source === 'fallback'` 时提示"示例数据 · 网络不可用"。

## 4. 搜索接口（本地索引）

文件：`src/api/search.ts`

```ts
interface SearchEntry {
  id: string; type: '景区' | '美食' | '活动' | '攻略' | '服务';
  title: string; subtitle: string; path: string; img?: ImgKey;
  tags: string[]; heat: number; body: string;
}
interface SearchHit extends SearchEntry { score: number; hits: string[] }

buildIndex(): SearchEntry[]                 // 首次调用构建并缓存
searchAll(query: string, limit = 12): SearchHit[]
hotKeywords: string[]                        // 8 个热词
```

**打分规则**（`src/utils/search.ts`）

| 字段 | 权重 |
| --- | --- |
| 标题 | 6 |
| 标签 | 3 |
| 摘要 | 2 |
| 类型名 | 2 |
| 正文 | 1 |

- 词频累加；整串完全相等额外 ×2。
- 未命中的词按中文二元组做**部分召回**（每次命中 × 权重 × 0.5），解决"熊猫基地" vs "大熊猫繁育研究基地"。
- 覆盖度加成：`score *= 1 + 命中词数/总词数`。
- 排序键：`score + heat / 100000`，降序。

## 5. 智能问答接口（本地知识库）

文件：`src/stores/chat.ts`、`src/data/faq.ts`

```ts
interface FaqItem { id: string; keys: string[]; question: string; answer: string; tags: string[]; link?: string }

matchFaq(query: string): FaqItem | null
useChatStore().ask(question: string): void
```

**匹配流程**

1. 关键词加权打分（问题×6、keys×4、tags×2、answer×1）。
2. 中文二元组 Jaccard 相似度：问题×15、keys×10，取较大值。
3. `total = 关键词分 + 相似度分`，阈值 5 分；低于阈值返回 `null`。
4. store 在 480-800ms 后追加机器人消息；`null` 时返回兜底引导（景点/美食/交通/行程四个方向 + 12345）。

**错误处理**：空输入直接忽略；`thinking` 期间忽略新提问，避免竞态。

## 6. 推荐接口

文件：`src/utils/recommend.ts`

```ts
recommendScenic(current: ScenicSpot | null, limit = 3): ScenicSpot[]
recommendFood(current: Food | null, all: Food[], limit = 3): Food[]
recommendGuide(current: Guide | null, all: Guide[], limit = 2): Guide[]
```

| 因子 | 权重 |
| --- | --- |
| 标签重合数 | ×10 |
| 同季节（景区） | +8 |
| 同辣度（美食） | +6 |
| 评分/热度折算 | 0-5 |
| 浏览量折算（攻略） | views/10000 |

## 7. 接口演进约定

| 现状 | 演进方向 | 影响面 |
| --- | --- | --- |
| 页面直接 import data | 改为 contentApi（已提供） | 仅改 8 处 import |
| contentApi 走 delay | 改为 fetch('/api/...') | api 层内部实现 |
| 搜索为内存索引 | 内容 > 500 条时改后端检索 | api/search.ts |
| 问答为规则匹配 | 可接 LLM 接口，保留兜底 | stores/chat.ts |

所有接口均为纯函数或返回 Promise 的模块函数，无全局副作用（除 localStorage 缓存与 Pinia 状态），便于单测与替换。
