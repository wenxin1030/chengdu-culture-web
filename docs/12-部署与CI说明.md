# 部署与 CI 说明

---

## 1. 构建

```bash
pnpm install --frozen-lockfile
pnpm build          # vue-tsc --noEmit && vite build
```

产物位于 `dist/`，为纯静态文件：

```text
dist/
├─ index.html
├─ robots.txt
├─ sitemap.xml
├─ favicon.svg
└─ assets/                 # 带内容 hash 的 js / css / svg
```

体积（gzip）：入口 JS 约 44 KB、vendor 约 43 KB、CSS 约 7 KB、SVG 合计约 150 KB（46 张，均有长期缓存指纹）。

## 2. 部署方案

### 2.1 GitHub Pages（课程演示推荐，零成本）

1. `vite.config.ts` 的 `base` 设为仓库子路径，例如 `base: '/chengdu-web/'`（若部署在 `<user>.github.io/<repo>/`）。
2. 使用 `gh-pages` 分支或 Actions 产物发布（见 `.github/workflows/deploy.yml`）。
3. SPA 需要 404 兜底：将 `dist/index.html` 复制为 `dist/404.html`，或在 Actions 中追加该步骤。

### 2.2 Vercel（推荐，自动 HTTPS）

1. 导入仓库，Framework 选择 Vite，Build Command `pnpm build`，Output `dist`。
2. 添加 `vercel.json` 做 SPA 重写：

```json
{ "rewrites": [{ "source": "/(.*)", "destination": "/index.html" }] }
```

3. 默认域名即 HTTPS，Lighthouse 的 is-on-https 项满分。

### 2.3 对象存储 + CDN

1. `dist/` 全量上传至 COS/OSS（`index.html` 设 `Cache-Control: no-cache`，`assets/*` 设 `max-age=31536000, immutable`）。
2. 开启静态网站托管，配置 404 → `index.html` 的 SPA 回退。
3. 绑定自定义域名并开启 HTTPS。

### 2.4 本地预览与验收

```bash
pnpm preview            # http://127.0.0.1:4173
node scripts/lighthouse.mjs      # 生成 lighthouse-reports/
node scripts/capture-shots.mjs   # 生成 .preview/shots/*.png 与溢出报告
```

## 3. CI（GitHub Actions）

工作流文件：`.github/workflows/ci.yml`

```text
push / pull_request
  ├─ setup Node 22 + pnpm（缓存 store）
  ├─ pnpm install --frozen-lockfile
  ├─ pnpm lint            （--max-warnings 0）
  ├─ pnpm typecheck       （vue-tsc --noEmit）
  ├─ pnpm test            （44 条单测）
  ├─ pnpm build           （类型检查 + 生产构建）
  ├─ 上传 dist 产物（artifact）
  └─ （可选 job）Playwright：安装 chromium 后跑 16 条 E2E（桌面 Chromium）
```

部署工作流：`.github/workflows/deploy.yml` —— 仅在 `main` 分支 push 且 CI 通过时触发，构建并发布到 GitHub Pages。

## 4. 环境变量

本项目**不需要**任何密钥。天气接口 open-meteo 免 Key；如将来接入真实后端，约定：

| 变量 | 用途 | 示例 |
| --- | --- | --- |
| VITE_API_BASE | 内容接口基地址 | https://api.example.edu |
| VITE_WEATHER_BASE | 天气接口基地址（可选自建代理） | https://api.example.edu/weather |

Vite 仅暴露 `VITE_` 前缀变量给客户端；**禁止**把任何密钥写入前端。

## 5. 发布检查清单

- [ ] `pnpm lint` / `pnpm typecheck` / `pnpm test` 全绿
- [ ] `pnpm build` 成功，`dist/` 可本地 preview 通过
- [ ] Lighthouse：性能 ≥ 80、可访问性 ≥ 80、SEO ≥ 80
- [ ] 390px / 1440px 无横向滚动（capture-shots.mjs 报告全 0）
- [ ] 部署后检查 SPA 深链（直接访问 /scenic/panda 不 404）
- [ ] robots.txt 与 sitemap.xml 中的域名与最终站点一致
- [ ] 页脚"关于本站"中的课程与组别信息正确

## 6. 回滚

静态站点回滚即切换产物版本：

- GitHub Pages：回退到上一个 `gh-pages` 提交并强制推送；
- Vercel：在 Deployments 中 Promote 上一个构建；
- 对象存储：保留 `dist-<git-sha>/` 目录，切换 CDN 回源路径。

由于资源文件名带 hash，回滚不会造成缓存串味。
