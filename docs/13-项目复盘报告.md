## 2. 关键决策复盘

### 2.1 视觉资源"程序化生成"而非找图

**背景**：任务要求城市宣传感，但课程环境不允许外链图床，也无法保证素材版权。

**决策**：写 51 张 SVG 生成器（山脊 Catmull-Rom、剪影构件库、7 套配色）。

**结果**：单张 3-12 KB、完全离线、风格统一，成为本站最强辨识度来源。

**代价**：迭代 3 次（屋顶/熊猫/美食构图），每次都要用 resvg 渲染 PNG 肉眼验收。

**教训**：生成式视觉必须"渲染即检查"，否则极易出现"代码正确、观感错误"。

### 2.2 智能化选择"可解释的轻算法"而非接大模型

**背景**：课程强调智能化，但没有提供模型 API 与预算。

**决策**：问答用"关键词加权 + 中文二元组相似度"，搜索用四级字段加权 + 二元组部分召回，推荐用标签/季节/热度。

**结果**：全部离线可跑、结果可解释、可单测；"熊猫基地几点去最好"能命中 panda-time。

**代价**：知识库只有 15 条，覆盖有限；需要兜底话术。

**教训**：小数据量场景下，"能命中 + 会兜底"比"模型很大"更能保障体验。

### 2.3 先建令牌再写组件

**背景**：12 个页面若各自写样式，后期改色改间距会失控。

**决策**：先定 tokens.css（调色板 → 语义 token），组件只用别名变量。

**结果**：深色主题只改语义 token 即全局生效；后期一次别名层补齐就修复了全局间距/圆角。

**代价**：初期多花约 3 小时整理变量。

**教训**：设计系统是"前期慢、后期快"的投资，且必须写"变量映射表"而非口头约定。

## 5. 团队协作复盘

- **有效做法**：按"设计系统 → 数据 → 组件 → 页面 → 测试"顺序推进，接口先定（types + data），页面开发互不阻塞；每次合并前跑 `typecheck + lint + test`。
- **不足**：视觉评审没有固定节奏，导致同一批 SVG 返工 3 次；智能化阈值调参缺少数据集，只能靠个例手测。
- **改进**：为视觉增加"验收清单"（可辨识度、配色一致性、移动端裁切）；为问答建立 20 条回归问句表。

## 6. 个人收获

1. 掌握了"设计令牌 → 组件 → 页面"的工程化落地方式，理解了为什么 UI 框架都要先抽象 token。
2. 第一次系统性地用 Lighthouse 驱动性能优化：从"感觉慢"到"定位到 SVG 滤镜与首屏占位"。
3. 理解了"可访问性不是加分项"：aria-live、label、焦点环、对比度都会直接体现在分数与体验上。
4. 学会用 Conventional Commits + 分支模型管理一次完整交付，知道 PR 评审该看什么。
5. 认识到"中文没有空格"对搜索/问答的深远影响，二元组是一个成本极低的解法。
